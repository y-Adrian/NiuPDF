# Mac PDF 阅读与标注软件：需求文档

参考对象：PDF Expert（Readdle）　|　目标平台：macOS　|　文档类型：功能需求清单 + MVP 规划

## 1. 产品定位与设计原则

PDF Expert 的口碑来自三点，也是本产品的设计原则：

1. **快**：大文件秒开，滚动、缩放不掉帧。
2. **原生感**：遵循 macOS 交互习惯（触控板手势、快捷键、多窗口、标签页）。
3. **标注是一等公民**：标注读写符合 PDF 标准，在其他阅读器中打开依然可见、可编辑。

**优先级定义**

- **P0**：MVP 必须有
- **P1**：第二阶段
- **P2**：差异化或锦上添花

## 12. MVP 范围

原则：先做出“好用”，再追求“强大”。

**第一阶段（约 4–6 周）包含：**

- 阅读与渲染：R-01 \~ R-04、R-07
- 导航与搜索：N-01 \~ N-04
- 标注：A-01 \~ A-04、A-08、A-09
- 页面管理：P-01、P-03
- 通用体验：U-01、U-02、U-04
- 安全与生态：S-02、S-04、Y-01

这套组合已覆盖“读论文 / 读手册并做笔记”的核心场景。

## 13. 技术选型建议

| 方案 | 优点 | 短板 | 适用阶段 |
| --- | --- | --- | --- |
| PDFKit（Apple 原生） | 开发最快，Mac 原生体验好，标注读写基于标准 | 复杂编辑能力弱，大文件性能一般 | MVP 验证 |
| PDFium / MuPDF | 渲染更可控，性能与兼容性更强 | 需自行实现 UI 层与标注交互，成本高 | 遇到瓶颈后替换 |

**架构要点**：将“文档模型 / 标注模型”与“渲染层”解耦，这样先用 PDFKit 验证产品，后续替换渲染层时不用重写业务逻辑。

## 14. 主要风险

- **A-09 标注标准兼容**：决定数据能否迁移，必须从第一天起按标准 PDF Annotation 写入，事后补救代价极高。
- **E-01 正文编辑**：涉及字体嵌入、重排与行距匹配，工作量极大，建议放到最后甚至不做。
- **R-01 大文件性能**：需尽早用 500 页以上的真实文档做基准测试，避免后期才发现渲染瓶颈。
