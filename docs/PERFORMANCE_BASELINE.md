# PDFKit 性能与互操作基线

测量日期：2026-10-17（Asia/Shanghai）  
环境：Apple Silicon，macOS 27.0.1，Xcode 27.1。输入为仓库中的 501 页合成 PDF。

## 命令行探针

`PDFKitPerformanceProbe` 在不改写输入的情况下测量文档打开、首页栅格化、全部页面缩略图和保存到唯一临时副本的耗时。临时保存文件会重新打开并核对页数，进程退出时删除。预览图也必须写到原输入以外的、新建路径。

一次测量结果：

| 项目 | 结果 |
|---|---:|
| 页数 | 501 |
| 打开 PDFDocument | 33.06 ms |
| 首页 900×1200 栅格化 | 18.88 ms |
| 501 页 128×176 缩略图 | 176.38 ms |
| 临时副本写入并重开验证 | 9.68 ms |
| 峰值 RSS | 34.94 MiB |

这是合成文档的一次 CLI 探针结果，不包含窗口布局、PDFView 首屏绘制、连续滚动帧率、外置卷宗或 iCloud 协作开销。机器负载与缓存会影响结果，不能作为性能承诺。

## 标注互操作

已执行 `PDFKit → pypdf → PDFKit` 往返：输入有一条标准高亮，第一遍加入一条标准下划线；第二种实现读写后再由 PDFKit 读取。最终页数、文本及一条高亮/一条下划线均保持。全过程对临时副本操作，语料原件未改写。

当前这只能证明 PDFKit 与 pypdf 对该合成样例的基础兼容。Preview、Chrome、Acrobat 的人工显示检查仍未完成；复杂外观流、透明度、坐标变换和第三方批注仍需扩充语料并验证。

## 已知限制

- 501 页连续滚动帧率尚未测量；需在应用 `PDFView` 窗口内做真实交互基准。
- 系统 Preview 在当前执行环境无法启动，因此未尝试打开或操作用户现有的 Chrome 会话。
- 合成 CJK 文件依赖 CID 字体资源。Poppler 环境缺少对应 Adobe CJK 字体包时渲染空白；macOS PDFKit 本机预览能显示中日韩文字和旋转内容。另需增加含嵌入字体及明确缺失字体的语料。
- PDFKit `write(to:)` 的 CLI 成功与可重开验证不等于应用已具备安全保存。应用保存需实现协调访问、外部变更检测、临时文件验证和原子替换后才可用于真实文档。
